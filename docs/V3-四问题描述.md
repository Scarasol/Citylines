## 2. 问题四：已定因（唯一有逐格证据的一条）

### 2.1 证据

用户运行的两条命令（原文）：

```
[citylines] chunk (-165,195) MODE=V3
  plan: supercell=D[-6,6] class=SECONDARY mask=0x8 transition=0x0 end=WATER
  plan reserves this chunk as a road: true   (needs a class AND at least one explicit logical edge)
  surface part: citylines:v2r_s_000s rot=0
  TLC: isCity=true rawRoad=SECONDARY effectiveRoad=SECONDARY couldHaveBuilding=false multiPos=MultiPos[x=-1, z=-1, w=1, h=1]

[citylines] chunk (-163,195) MODE=V3
  plan: supercell=D[-6,6] class=NONE mask=0x0 transition=0x0 end=NONE
  TLC: isCity=true rawRoad=NONE effectiveRoad=NONE couldHaveBuilding=true multiPos=MultiPos[x=-1, z=-1, w=1, h=1]
  TLC: hasBuilding=true plannedRoadType=NONE isPlannedRoad=false
```

同一行的 sweep（`/citylines sweep -166 195 -159 195`）：

```
plan  z=195 SS...SSS          x = -166 -165 -164 -163 -162 -161 -160 -159
mask  z=195 a8...2aa
eff   z=195 SS...SSS   bld=...yy...
```

存档实测（只读解析 `run/saves/新的世界`，用正确的 `block_states` (y,z,x) 索引）：

- 路面：-166 / -165 / -161 / -160 / -159 每格 256 块路面，**一律 y=71**；
- 空洞 -164..-162：无任何路面材质；-164 是广场（`grass_block`×209 + `smooth_stone_slab`×46 @y=72），
  -163/-162 是多层建筑（楼板 y=69~88、玻璃、梯子 y=53~62），**洞内外同高**；
- 该行地道：-166 y=54、-165 与 -159 y=66 有铁轨；
- 该区群系：所有 section 全是 `plains`，**不是海洋/河流/沙滩**。

### 2.2 结论

1. `eff == plan` 逐格相等 → **TLC 没有剥夺任何"计划中的路"**；建筑正是落在**计划自己的 3 格空洞**里。
   → "建筑占路"的表现=计划空洞被 TLC 正常填入建筑（TLC 的建筑否决清单里没有"水"，只看
   `plannedRoadType`、随机、高速、铁路、预定义内容；`BuildingInfo.checkBuildingPossibility` L522-570）。
2. 计划为何在那里留下 3 格空洞：`end=WATER`（`blockedReason` 对一度端点的归因）。群系是 plains，
   所以触发的是**另一条**判据：`TlcRoadFacts.factsAt()` 里

   ```java
   boolean belowWaterLine = belowWaterLine(heightmap.getHeight(), waterLevel);  // OCEAN_FLOOR < 海平面
   boolean water = LostCityTerrainFeature.isWaterBiome(provider, coord) || belowWaterLine;
   ```

   用的是**城市生成之前**的天然河床高度。而 TLC 自己只在 `waterLevel > groundLevel`（全城淹水
   profile）时才在城市格里灌水，否则把地表整平到 `getCityGroundLevel()`（`doCityChunk` L908-942）
   ——所以被城市填平盖起来的旧河道是**陆地**，我们却判成了水格。
3. 因此：**问题四的成因是 fact 源的"水"判定误报**（把规划用地误判为水），不是 TLC 裁路权、不是
   层高变化、也不是车站结构。我的"车站"推测已被该证据证伪。

## 3. 问题二（y 跳变）：现状与证据边界

这一条**没有**像问题四那样拿到逐格证据，诚实记录如下。

### 3.1 已确证的事实

1. **高度函数我们没有改**（两路独立审计确认）：每格层高 = 该格地形高度落在哪个"每 8 格一级"的
   分带（`getLevelBasedOnHeight`，`CITY_LEVEL0..7_HEIGHT = 75/83/91/…/131`）；地形高度**每 3×3
   区块采一个值**，取该组中心那一格（`ChunkHeightmap` + `heightSampleSize=3`）；每级地面差 6 格
   （`FLOORHEIGHT=6`）；`groundLevel=71`（profile `default.json`）。`useAvgHeightmap=false`。
2. 单区块内**路面高度 = 地形整平高度 = 建筑地面高度**（同一表达式 `groundLevel + cityLevel×6`），
   这一条是审计逐行确认的硬结论。
3. 20~30 格 = 4~5 级 ⇒ 只可能来自两类：**(A)** 层高场本身的台阶（相邻采样组的高度差 ≥32 格，
   陡坡地形）；**(B)** 某一格**没有被整平**（非城市格保留自然地形紧邻整平到 y=71 的城市格）。
   楼梯/坡道（一次只补 1 级 = 6 格）在数量级上**不可能**解释 20~30 格。
4. 我们的模组能碰到高度的注入只有 3 条（两处多建筑降级 + LC2H 占位，后者你环境未装）。多建筑降级
   会让该格从"足迹平均层高"变成"逐格层高"。
5. 平衡前后对比（合成地形仿真，按 LC 规则）：现状山地相邻格 17.61% 有台阶、6.55% 有 ≥2 级大台阶、
   最大落差 26 格；断崖 20.57% / 13.80% / 48 格。

### 3.2 未确证 / 未做

- 未拿到"用户看到的那处跳变"的两个区块坐标，因此**没能判定**它属 (A) 还是 (B)。
- 未在游戏内验证任何高度改动。
- 我先前给过的两类解释都被用户判定与观感不符并已作废（附录 B）。

### 3.3 审计另查出的、与高度同源但用户判定本轮不处理的项

- 层变楼梯被 `suppressStairs` 整段删除（原版 4 种楼梯件里 6 格宽的两种必然压到我们的车行道
  → 必删，约一半层变点失去楼梯，只剩 6 格直立面）；
- `generateRandomVegetation` 的 `zoneTouchesPaved` 判定与实现不符（实为无条件取消树叶带）；
- 本地路 `throughAt` 缺逐格层高检查（已列入决策 D11，本轮修）。

## 4. 问题三（稀疏）与问题一（形制）

- **问题三**：已核对的成因有四类——(a) 设计间距（S=30 区块，每方向一条集散轴）；(b) 等层高连边
  + `dropIsolatedCells`（有等级但无显式边的格会被从计划里删掉）；(c) 缺口修复只补 1~2 格，3 格洞
  不补也不试绕行；(d) 硬障碍/水判定误报（问题四那条）。决策 D10/D11 对应 (c) 的邻域与正确性。
- **问题一**：几何实测主干车行道 10 格、次级 8 格、本地 6 格 → 16 格断面内 10 与 8 只差 2 格，
  用户判定不可接受；决策 D4 已定新断面。

## 附录 A：两路独立审计的结论摘要（只读，未改任何文件）

**审计一（注入面，9 条注入逐条核）**

- 只有 3 条能真正改变"高度/整平/落位"：`BuildingInfoMixin`→`V3RoadRights` 的多建筑降级、
  `MultiChunkMixin` 的候选否决、LC2H 占位（未装）。其余注入（桥面替换、桥规划器关闭、街道铺装
  接管、植被/装饰压制）**不改高度**。
- 世界样式替换在默认 `standard` 下**高度中性**（城市概率乘子走 `profile.getWorldStyle()` 字符串，
  不受替换影响；多建筑参数逐项相同）。
- 我们提前读层高/高度图只写两个**纯值缓存**，读到的值与生成时应有的值相同 → **没有缓存污染**。
- 副作用一条：`/citylines chunk|sweep` 会调用建筑特征查询，**在尚未生成的区块上运行会提前冻结
  它们的建筑判定**；建议只在已生成区域使用。

**审计二（计划 → 渲染）**

- 11 条落差路径，其中三条【高】：(1) 层变楼梯被我们删除；(2) 层变处我们变成空地，而原版街道网
  （主干每 8 区块、本地路 40% 概率）会在那里铺路并因此得到坡道/楼梯；(3) 坡道格绕过我们的渲染
  （我们故意不 hook `generateStreetSlopeSection`）。
- **否定了我先前的一个说法**：多建筑平均层**不会**造成"我们渲染的两段路之间"的高差（多建筑格
  永远是建筑格）；它只造成"我们的路 ↔ 旁边建筑格"的 6k 台阶。
- 硬结论：单区块内路面高度与整平高度必然一致。
