## 1. 这一版改了什么

把"每 2048 格采样、再量化到 6 格台地"的 `LEGACY` 规则保留为默认，新增一条**维度级统一平面**规则 `UNIFORM`：
适用城市区块的地面一律是冻结 profile 的 `GROUNDLEVEL`（本存档 71），城市层高恒为 0，
因此**城内道路地面零落差是构造保证**，不再依赖采样与平滑的概率。

### 与策划案的两处**有意偏离**（需你知晓）

1. **激活门用 `CreateSpawnPosition` 而不是扫描 `region/*.mca`**。理由：Forge 这个事件正是"游戏自己新建了这个世界"的信号，Lost Cities 自己就用它判定新世界（`LostCityWorldGenData.initializeNewWorld`），且它的处理器当场就取到了维度 profile。比"目录里有没有区块文件"更贴语义（空存档目录、外部存储实现都不会误判）。代价：若某个已有世界因为别的原因再次触发该事件，且它**没有**我们的记录，就会被当成新世界（策划案 §8 的"无记录不代表新世界"就靠这个事件保证）。**未验证**，建议作为下一步加固：把 region 文件检查作为第二个条件。
2. **记录在写入后立即 `getDataStorage().save()`**，不等世界存档。理由：实测本环境只能用硬杀停服（Windows 下无窗口进程无法优雅关闭），不即时落盘则身份会丢，重载就可能重新决策。这是让 §8 的冻结真正成立的必要条件。

## 9. E：LC2H 两处城市高度门槛强制走精确原始高度（2026-09-27，经授权实施）

### 9.1 改了什么

`Lc2hCityHeightGateMixin` 现在覆盖 LC2H 两个 helper 里的**两条互斥取高度分支**（`lc2h$getCityFactorUncached` 与 `lc2h$finishNormalCityFactor`，每个方法各 2 处注入，共 4 处，全部 `require = 1`）：

| 分支 | 原来的行为 | E 之后（仅 UNIFORM 生效的维度） |
|---|---|---|
| `shouldAvoidBlocking() == false` → `getHeightmap(coord).getHeight()` | 读工作高度（可能已被城边整形改写） | 投影到冻结 raw 快照；无快照 ⇒ 哨兵 ⇒ **门槛拒绝** |
| `shouldAvoidBlocking() == true` → `NaturalHeightSampler.LevelSampler.cachedChunkHeight(x,z)` | 缓存命中读"已生成区块"的高度（在平面上即压平后的 71 ⇒ 自我反馈）；**未命中 ⇒ 返回 null ⇒ 整段跳过门槛** | 改走 `provider.getHeightmap(...)` → raw 快照；**绝不返回 null**（null 是 LC2H"高度未知⇒跳过"的信号）；无快照 ⇒ 哨兵 ⇒ 拒绝 |

非 UNIFORM 维度一律 `original.call(...)`，行为与 LC2H 原样一致。

### 9.2 对 LC2H 的性能优化有什么影响（逐项核对）

**不动**：`NormalCityFactorTileCache`（瓦片因子缓存，在门槛之前）、`MixinCity` 对 `getCityFactor/isCityCenter/getCityRadius` 的覆写与各自缓存、RNG 结果缓存、`PlannerHotPath` 策略本身（17 个类在用）、`AsyncHeightmapCoordinator` + LC2H 自有 heightmap 缓存与预算、`TerrainCorrectionGpuPipeline`、`preserveNaturalTerrain`/`skipInteriorCorrection`、快速多区块规划、`LostCitiesGenerationLocks`。

**自然高度缓存不会被废掉**：`cachedChunkHeight` 在 forge 包里有 9 个引用类，那两处门槛只是其中 2 个，其余（`CityShiftField` 地形整形、`MixinBlenderCityEdge` 城边混合、`MixinDefaultDimensionInfoHighwayHeightGate` 高速高度门槛、`CityTerrainPlanBridge`、`MountainCityReservationPlanner`、`BiomeInfoRuntimeCache`、诊断）**照旧读缓存**，`publishResidentChunk` 的预取仍然有用。

**唯一被拿掉的**是那条"热路径 + 缓存未命中 ⇒ 跳过城市高度门槛"的捷径——策划案 §4.4.4 点名要删，而且它有两种坏法：冷缓存＝门槛不生效，热缓存＝读到已被本方案压平的高度（自我反馈）。

**成本（2026-09-27 更正，原表述作废）**：查询次数不变（门槛本来每次都跑），只是取值来源改变。LC 的 `generateHeightmap` 只采**区块中心一列**（`getBaseHeight(cx+8, cz+8, OCEAN_FLOOR_WG, ...)`），一个 heightmap 由采样组共享（`heightSampleSize=3` ⇒ 9 个区块），因此"每个采样组一次中心列求值"是一个**结构下界，不是上限**：LC/LC2H 的高度缓存会逐出，`AsyncHeightmapCoordinator` 在同键未完成时可在当前线程**重复求值**（不等待，但会重复算），所以一次会话内同一采样组可能被重算多次。命中路径相比 `forLevel()`+`ConcurrentHashMap.get` 不更慢、也没有新增等待协议，但**总成本未经实测**，要数字必须能跑 LC2H。

**递归风险**：门槛里调用 `getHeightmap` 并非新引入——`shouldAvoidBlocking()==false` 的原生分支本来就这么调；E 只是让热路径走同一条已存在的调用。

### 12.2 五项核阅问题如何关闭

| 问题 | 当前实现 | 开销与边界 |
|---|---|---|
| provider / generator 空值早退绕过冻结 | `decision()` 先处理 NOT_READY/BROKEN，再处理空 provider/generator，再查决策缓存。READY 丢失必要输入会 BROKEN 并拒绝生成 | 常数次状态读取，不新增地形采样。真正非 LC 维度仍走原路径 |
| 旧 LEGACY 世界误开 raw 适配 | `expectsPlane()` 只对已确认适用的 UNIFORM 激活候选、READY/BROKEN 生效。LEGACY/OFF/UNSUPPORTED 永不启用 | 不因全局配置为 UNIFORM 而改变旧世界的 LC2H 取值行为 |
| EC 事后轮询过晚 | 在 EC 原有同步 `setLostCityBuildingOverrides` 发布记录之前，检查完整候选列表的矩形及 suppressedChunks；失败直接拒绝修改。通过后更新持久身份 | 删除每 512 次生成扫描。只在激活或显式覆盖编辑时扫描，上限 65,536 次区块访问；未变化记录不在生成热路径重复扫描 |
| 身份只含懒加载资产名，未知项通配 | `uniform-v2` 精确匹配。用正式 datapack registry + Codec/RegistryOps 编码世界风格、预定义城市、多区块定义的完整内容，再做规范化 JSON SHA-256；加入采样选项、profile 名和 EC 足迹内容摘要 | 每维度初始化一次，EC 编辑只重算覆盖列表摘要。不再读 lazy AssetRegistries 的已加载子集，不写入 `?`，不按未知项放行 |
| 异常后 ThreadLocal 帧泄漏 | 包装 worker 内真正 `doFill` 调用和两处 `iterateNoiseColumn` 调用，统一由 `withContext` 的 `try/finally` 恢复原帧 | 保持既有 MixinExtras 0.3.6，不升级依赖，不等到下次 fill 再清理；无逐方块分配 |

缺 raw 高度现在立即锁定 BROKEN 并抛出，不先返回伪造 factor 让 LC2H 缓存。EC 预检若遇到此类契约失败，不得再把 BROKEN 覆盖成 UNSUPPORTED。

状态边界不变：**从未激活**且能力不足可以 `UNSUPPORTED -> 原生`；**已经冻结 UNIFORM**不能静默回原生。NOT_READY 不能产出或缓存永久回退。

资产摘要目前覆盖上述三类完整注册表，不做单个维度的依赖裁剪。因此更换这些资产内容，即便某个资产尚未被该维度用到，也会触发身份不匹配；没有暗中接受 datapack 热迁移。

### 12.3 联测发现的必要接入修复

1. LC2H 覆写 `BuildingInfo.getCityLevel` 后没有 `getCityLevelLocked` 调用。旧挂钩实际会启动失败。本轮保留原生 TLC 挂钩，并由插件互斥选用新 `Lc2hCityLevelMixin`：在 public 方法 HEAD 优先返回统一层高；非压平格在 RETURN 保留原有 D6/D7 平衡，邻格原始查询用异常安全的线程标记避免递归。没有改动平衡算法。
2. LC2H 两处城市高度门槛严格按策划指定分支处理：只把门槛位置的 `shouldAvoidBlocking()` 改为 false，读取精确 heightmap/raw snapshot。前面的 tile-cache hot-path 判定保留；null sampler 也不能绕过门槛。没有全局关闭 LC2H 缓存或异步机制。
3. EC 已冻结维度的 `setGenerateLostCities`、`setLostCitiesProfile`、`setLostCitiesWorldStyle` 在发布前拒绝改变生成规则；相同值允许，未冻结维度不受限。这是冻结契约的必要边界，不是新的城市模型特判。
4. 原生 `SavedData.save` 会吞掉写盘异常，不能作为“身份已保存”的凭据。新增 `saveChecked`，只对本模组的 `citylines_city_ground.dat` 写临时 NBT 后替换，错误上抛；不改全局 SavedData 行为。支持时采用原子移动，不宣称跨文件事务或断电级 fsync 保证。EC 记录与本记录不是一个事务，写入失败会锁定 BROKEN，重载不匹配时拒绝继续生成。
