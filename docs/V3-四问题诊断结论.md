# V3 四个实测问题：诊断结论与修复建议

日期：2026-09-25。用户实机验收反馈四个问题（**用户判定不可辩驳**）：

1. 三个等级的**形制过于近似**——10 格 vs 8 格车行道在 MC 里看不出区别；
2. **y 轴跳变/漂移**；
3. 道路**过于稀疏**；
4. **建筑占据道路**。

**诊断方式**：分批读取 `run/logs/` 全部归档日志（含 `debug-*.log.gz` 与 `2026-09-25-*.log.gz`），
以及 `/citylines chunk` 的运行时输出。未改动任何生成逻辑。

---

## 1. 核心因果链（四个问题**同源**）

```
城层高度在城区内部变化（y 跳变）
        ↓
V3 连边要求相邻格 cityLevel 完全相同（14 处判定，见 §3）
        ↓
层变处无显式逻辑边 → 路格 mask=0
        ↓
① dropIsolatedCells 把这些格从计划里删掉        → 道路变稀疏（问题 3）
② isReservedRoad = "有等级 AND mask≠0" 为假     → 该格不占路权（问题 4）
        ↓
③ TLC: plannedRoadType != NONE 的建筑否决失效   → 建筑可以生成在路上
        ↓
主轴被切成短段，观感上"看不到主干"（问题 2 与 3 叠加）
```

**直接证据**：`/citylines chunk 0 -1` 的运行时输出

```
plan: supercell=D[0,-1] class=PRIMARY mask=0x1 transition=0x0 end=LEVEL_CHANGE
```

`mask=0x1` = 只有北向一条边 → 该格南侧**因层高变化而断开**，
终止原因被规划器**明确标注为 `LEVEL_CHANGE`**。
而同一条轴上的铺设 y 值实测为 `89 → 113 → 83`（差 24~30 格）。

**策划案依据**：《方案》§13 要求主干"**跨多个规划单元的穿行骨架；只在城市/同层可铺设分量边界或硬障碍处合法终止**"。
**因层高在城市内部断开不符合策划案，是缺陷而非设计。**

---

## 2. 各问题的独立证据

### 问题 2（y 跳变）— **已确诊**

日志 `2026-09-25-5.log.gz` / `debug-5.log.gz`，**同一条主轴 `x=0`**：

```
v2r_p_000p at -4,0   y=101
v2r_p_000p at -6,0   y=107
v2r_p_0p0p at -7,0   y=107
v2r_p_000p at -8,0   y=107
v2r_p_000p at -9,0   y=77     ← 30 格跳变
v2r_p_0p0p at -10,0  y=77
v2r_p_000p at -11,0  y=77
```

`y` 来自 `info.getCityGroundLevel()`，即"本格所在城层的地面高度"。
**同一轴上的相邻格属于不同城层 → 路铺在不同高度 → 视觉断裂。**

### 问题 3（稀疏）— 已确认两条成因

- **设计因素**：主干间距 `S = M*K = 30 区块 = 480 格`；每方向每超单元只有 **1 条**集散轴。
  抽象全城市同层占比 15.2%（P 6.6 / S 5.4 / T 3.2）。
- **缺陷因素**：上述层变断边 → `dropIsolatedCells` 删除孤立格 → **实际可见道路少于 15.2%**。

各会话前 8 件（INFO 上限）的等级构成差异极大，印证不稳定性：
13:52 → 主干 2 / 次级 6；09-25-9 → 主干 6 / 次级 2；**09-25-10 → 主干 0 / 次级 8**；14:11 → 主干 8 / 次级 0。

### 问题 4（建筑占路）— **因果已定位，但缺少当场取证的日志**

单格建筑占路的**唯一**入口是 `plannedRoadType == NONE`（否则 `BuildingInfo` 的
`b = false` 会否决建筑）。而 `plannedRoadType` 变 NONE 的原因中，
**"计划有等级但 mask=0"**（即问题 2/3 的同一根因）会同时满足：
`isReservedRoad` 为假 → V3 路权不占 → TLC 建筑否决失效 → **建筑落在原本计划为路的位置**。

**这一条我标注为"因果链完整、但当场的逐格证据尚未取得"**——
现有日志只在**成功铺设**时打印，`placeV2Section` 返回 false（含路权被裁）时是静默的，
所以无法直接看到"该格本应有路、却因被裁而让给建筑"。

### 问题 1（形制近似）— 用户判定，数据支持

部件几何实测：主干车行道 **10 格**、次级 **8 格**、本地 **6 格**（断面 `walk/kerb/carriageway` = `2/1/10`、`3/1/8`、`4/1/6`）。
**（2026-09-25 更新：该断面已被决策 D4 取代——现为 `1/1/12 + 两格中央线`、`2/1/10`、`4/1/6`；本行保留为当时的实测记录。）**
在 16×16 区块里，10 vs 8 只差 **2 格**（12.5%），确实难以分辨。
**策划案要求"三级必须有功能与尺度差异，不能只换颜色"**，所以这属于**设计未达标**，需要重做形制。

## 3. 修复范围评估（为什么不能"改一行"）

V3 里要求"相邻格同层"的判定共 **14 处**，分布在连边、面提取、绕行、本地路端点、
缺口修复、枢纽判定等各阶段：

```
L300, L316, L361, L369, L423, L469, L493, L522,
L674, L845, L852, L927, L979, L1161
```

因此"允许层高容差"**不是局部改动**，会牵动选线、面统计、路权与终止归因。
**必须成套修改并重测全部抽象证据**（且用户已同意盐沿用 3）。

---

## 4. 建议的修复方案

### P0 — 层高容差（解决问题 2，并同时缓解 3 与 4）

- **允许主轴/集散轴在"层高差 ≤ 1"处仍连边**（坡道仍禁用：只连边、不铺坡道、不承诺跨层通行）。
- 依据：策划案 §13 要求主干"只在城市/同层铺分量边界或硬障碍处终止"；
  用户也明确"同高度山地台地可有路"是允许的。
- **收益**：主轴连续 → 直接解决问题 2；减少 `dropIsolatedCells` → 缓解 3；路格恢复 mask → 路权恢复 → 缓解 4。
- **代价**：需改 14 处判定中的连边相关部分，并重测抽象证据。

### P1 — 让"路权被裁"不再静默（为问题 4 取证，并作为回归防线）

- `placeV2Section` 在"计划有路但 `isPlannedRoad()==false`"时打印该格的
  `plannedRoadType / hasBuilding / isCity / multiPos / V3 class / mask`。
- 同时**解除 INFO 上限**：每个等级各记前 N 件 + **一条汇总行**（`P=.. S=.. T=..`）。
- 纯诊断，不改生成行为。**这是解决问题 4 与验证 P0 效果的前提。**

### P2 — 形制差异化（解决问题 1，**需你确认设计**）

10/8/6 的差别不够。可选方案（需你选定，因为策划案有明确约束）：

| 方案 | 做法 | 与策划案的冲突风险 |
| --- | --- | --- |
| **A. 拉开车行道宽度** | 改为 `12/8/4`（主干更宽、本地更窄） | `2*(walk+kerb)+carriageway==16` 下 4 格车行道仅容一车，需你判断是否可接受 |
| **B. 材质区分** | 主干用深灰/抛光、次级用灰、本地用浅灰 | 策划案只给了"候选材质"，未冻结；风险低 |
| **C. 标线/中央分隔** | 仅主干加中央分隔或标线 | ⚠️ **策划案明确**："不默认铺连续白/黄混凝土中线……旧宽街通幅石英带的失真不能换一种颜色重现" |
| **D. 步行带比例区分** | 主干窄步行带+宽车行、本地宽步行带+窄车行 | 与 A 同属断面重做，风险低 |

**我的倾向**：**A + B 组合**（宽度拉开 + 材质区分），避开被策划案否掉的 C。
但**A 会改动 `RoadSection`，属于形制变更**，按你的要求我先不动，等你选。

# 追加（2026-09-25 晚）：用户两项关键纠正 + 新增证据

## 纠正 1：占据道路的是**单区块建筑**，不是多建筑

我先前的多建筑假设**方向错了**。用户明确：截断道路的是**单格（单区块）结构**。
按 `BuildingInfo.checkBuildingPossibility`，单格建筑落在某格需要该格
`plannedRoadType == NONE`（否则 `b = false`）。所以那一格必然是：

- **`plannedRoadType` 被解析为 NONE**，而计划里那一格有路等级。

## 纠正 2：整个城市的 y 都在跳，且是 (a) 型——**同一片连续街区内相邻建筑地面差 20-30 格**

这**不是**正常的分层，是异常。对应的机制已定位到：

```java
// BuildingInfo L402-404
if (characteristics.multiPos.isSingle()) {
    characteristics.cityLevel = getCityLevel(coord, provider);      // 逐格高度
} else {
    characteristics.cityLevel = profile.MULTI_USE_CORNER
            ? getTopLeftCityLevel(...) : getAverageCityLevel(...);  // footprint 平均高度
}
cityLevel = characteristics.cityLevel;                              // 存进 BuildingInfo
groundLevel = ...;                                                  // L870-873
public int getCityGroundLevel() { return groundLevel + cityLevel * FLOORHEIGHT; }
```

**`multiPos` 决定用"逐格高度"还是"整块平均高度"**。
`MULTI_USE_CORNER` 默认为 `false`，所以多建筑走 `getAverageCityLevel`。
若 V3 的路权否决改变了多建筑的**落位/尺寸**，则哪些格走平均、哪些格走逐格就会偏离原生，
**相邻建筑地面高度因此出现 20-30 格跳变**。

## 我的世界数据扫描已作废（方法学缺陷）

我写脚本从世界存档统计"主轴区块是否有路面材质"，但**无法区分道路材质与建筑内部装饰**：
实测 `y=4` 那一层同时含 `gray_concrete`、`light_gray_concrete`、`mossy_stone_bricks`、树叶，
明显是建筑/遗址内容，不是街道。故"80% 主轴无路"这个数字**作废**，不得引用。

## 新增诊断命令：`/citylines sweep <x0> <z0> <x1> <z1>`

一次打印一个矩形内**每格**的四列，避免再靠推理：

```
/citylines sweep -75 60 -75 75
  plan  z=60 PPPPPPPPPPPP...      ← 计划等级（P/S/t/.）
  mask  z=60 5a5a.........        ← 显式逻辑边；0 表示任何消费者都不当它是路
  eff   z=60 PPPP....   bld=...yy ← TLC 最终解析的路类 + 是否有建筑
```

**判读（也是我下一步要做的修复分类）**：

| plan | mask | eff | bld | 病根 | 修法 |
| --- | --- | --- | --- | --- | --- |
| P/S | **0** | NONE | y | **断边** → 路权失效 → 建筑占格 | 放宽连边条件（层高容差） |
| . | 0 | NONE | y | 规划层没排路 | 稀疏/参数 |
| P/S | ≠0 | NONE | y | TLC 侧裁剪（`isCity`/`multiPos`/预定义） | 查那条具体裁剪 |
| P/S | ≠0 | P/S | y | **真·路权失效**（预判之外） | 新查 |
